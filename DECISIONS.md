# DECISIONS

## 1. Ошибки файла и ошибки строки разделены
Файл читается через Files.newBufferedReader в try-with-resources: читается по одной строке, файл закрывается автоматически, номер строки считается счётчиком. Ошибки ввода-вывода превращаются в проверяемое ImportFileException и завершают импорт целиком. Ошибка строки (ImportRowException из парсера или причины из ValidationResult) записывается в ImportResult с номером строки, и цикл идёт дальше. Общего catch вокруг всего цикла нет: каждая строка обрабатывается в отдельном методе processLine со своим локальным try/catch.

## 2. Политика дубликатов сосредоточена в ValidationRules
Вариант 6, политика дубликатов, значение 35: повторная корректная запись с тем же ИНН заменяет прежнюю (побеждает последняя), но не более 35 замен за один импорт, дальше дубликаты отклоняются с причиной. Число лежит в ValidationRules.MAX_DUPLICATE_REPLACEMENTS и проверяется методом canReplaceDuplicate, импортёр только вызывает его. Разбор, проверка, сохранение и отчёт разнесены по классам ClientCsvParser, ClientValidator, ClientRepository и ImportResult, ClientImporter только координирует.
